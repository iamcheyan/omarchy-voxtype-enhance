# 运行时问题记录

## NixOS 上缺少 Voxtype OSD 前端

在 NixOS 上，Voxtype 可能只提供 `voxtype` 和 OSD 启动器，却没有同时提供
`voxtype-osd-gtk4` 或 `voxtype-osd-native`。这种情况下 daemon 启动时会反复
尝试启动 OSD 子进程，并记录类似下面的日志：

```text
voxtype-osd: neither 'voxtype-osd-native' nor 'voxtype-osd-gtk4' was found
on PATH or next to this binary.
```

这不会阻止录音、模型加载、转录或插件的顶栏状态显示；它只会让日志出现
重复错误，并且没有浮动的音量反馈窗口。

### 本插件的处理方式

本插件已经在顶栏显示 recording/transcribing 状态，因此默认关闭 Voxtype
的独立 OSD，避免在没有前端的 NixOS 安装上产生无效的重试：

```toml
[osd]
enabled = false
```

用户如果需要独立 OSD，可以改为 `enabled = true`，并安装与当前 Voxtype
版本匹配的 `voxtype-osd-gtk4` 或 `voxtype-osd-native`。安装前应确认该前端
来自同一个 Voxtype 版本，避免 ABI 或配置不匹配。

### 排查命令

```sh
voxtype config
command -v voxtype-osd-gtk4
command -v voxtype-osd-native
journalctl --user -u voxtype.service -b --no-pager
```

验证 daemon 本身仍然正常运行：

```sh
systemctl --user is-active voxtype.service
voxtype status
```

## NixOS 上缺少 Voxtype 本体

如果只安装了插件而没有安装 Voxtype，Arch/Omarchy 路径可能会提示通过
`pacman` 安装 `voxtype-bin`。NixOS 不提供 pacman，因此插件现在会明确提示
使用声明式系统配置安装 Voxtype，不会执行这个命令。

在本机可以把 `voxtype-onnx` 加入 NixOS 配置，然后执行系统 rebuild。插件
只负责配置已经存在的 Voxtype，不负责绕过 NixOS 的包管理流程。
